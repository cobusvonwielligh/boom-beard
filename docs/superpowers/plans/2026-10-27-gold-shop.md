# Persistent Gold Shop Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Turn lifetime collected gold into a persistent spendable wallet, let dead/intermission players queue capped next-spawn perks, shorten intermission to 16 seconds, and reduce ordinary non-gold floor drops by 20% without changing gold's absolute drop behavior.

**Architecture:** Keep the economy authoritative in the existing leaderboard and room. Put immutable shop catalog/cap rules in a shared module, persist only lifetime spend plus a pending queue, derive wallet from collected minus spent, and consume the queue exactly once while constructing a connected human's next spawned player. The browser renders private state returned by two small WebSocket messages and never decides whether a purchase is valid.

**Tech Stack:** Node.js ES modules, the existing authoritative simulation and WebSocket protocol, JSON leaderboard persistence, browser DOM/CSS/SVG, and `node:test`.

---

## Constraints to preserve throughout

- Do not include or overwrite the unrelated pending favicon and HTML edits already in the worktree.
- Keep `leaderboard.json` at version 1; new fields are additive defaults.
- Keep `coins` as lifetime gold collected. Derive `wallet = max(0, coins - spentCoins)`.
- Never send another player's `pendingShop`; normal score messages may expose only the derived wallet.
- Existing floor-perk caps remain the source of truth: speed 4, shield 2, stim 4, fire radius 5 from a starting radius of 1.
- Thin only the ordinary `maybeDrop` path. Direct earned gold, explicit `drop(...)` calls, and death scatter retain their current behavior.
- Use the existing SVG symbols, Clegan cast-gold classes, floor-perk palettes, and sound vocabulary. Add no replacement art or audio.
